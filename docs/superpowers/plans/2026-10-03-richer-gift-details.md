# Richer Gift Details Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add optional link and price to gifts and gift plans (plan overrides gift), show them in the UI, and show per-person / per-event budget totals.

**Architecture:** `url`/`price` columns on `Gift` and `Relation`; `Relation.effective_*` falls back to the gift. A `BudgetService` aggregates `Coalesce(relation.price, gift.price)` in the database over `Relation.objects.accessible_by(user)`. Forms get the two fields in a shared collapsed template section. Currency is a per-user display setting on `Profile`.

**Tech Stack:** Django 5.1, PostgreSQL, Bootstrap/HTMX, pytest (`tox run -e py311 -- <path>`), Playwright (`tox run -e e2e`), ruff (`tox run -e lint`).

**Spec:** `docs/superpowers/specs/2026-10-03-richer-gift-details-design.md`

## Global Constraints

- All code, docstrings and comments in English; user-facing strings wrapped in `gettext`/`{% trans %}` and added to the FR catalogue (`python manage.py makemessages -l fr`, translate, `compilemessages`).
- URL scheme must be `http` or `https` only; links render with `target="_blank" rel="noopener noreferrer nofollow"`.
- `price`: `DecimalField(max_digits=10, decimal_places=2, null=True, blank=True)`, DB check `price IS NULL OR price >= 0`. `url`: `URLField(max_length=2000, blank=True, default="")`.
- `Profile.currency`: `CharField(max_length=3)`, choices EUR/USD/GBP/CHF/CAD, default `EUR`. No currency conversion.
- Planned total = every plan except Abandoned; Spent total = plans in Purchased or Given. Plans with no effective price are ignored in sums and counted as "without price".
- Budgets only read `Relation.objects.accessible_by(user)`; per-person totals use plans whose `person` is that person (not group plans).
- The url/price form fields live in a collapsed section (closed by default; open when a field has a value or an error; works without JS via `<details>`).
- Use the existing factories in `gift_manager/tests/factories.py` (`GiftFactory`, `RelationFactory`, `RelationStatusFactory`, `UserFactory`, `PersonFactory`, `EventFactory`). Use PostgreSQL for tests.
- Do not add dependencies. Review the generated migration before committing.

## Review Focus

- Hostile URL (`javascript:alert(1)`, `data:text/html,...`, `ftp://`, scheme-less `example.com`) in gift or plan form -> rejected with a field error. (Task 2)
- Price `0`, `-1`, `1e3`, `12.345`, `abc` -> `0` accepted; negative/non-numeric/too many decimals rejected. (Task 1, 2)
- Clearing a plan override must revert to the gift value, not store `0`/empty as an override. (Task 2)
- Budget must not leak totals of plans the user cannot access (viewer/no-access cases). (Task 4)
- Gift without price and plan without price both absent: total is `0` with "without price" count, not an error / `None`. (Task 4)
- Hostile gift name / URL text in card, detail and Grid.js output stays escaped. (Task 5)
